# Tesla сервис — контекст для Claude

Владелец — начинающий специалист по сервису/софту Tesla в Грузии (импортные машины из США, часто после аварий). Опыта пока мало: объяснять просто, по-русски, по шагам. Цель — максимум автоматизации, Claude выступает ИИ-помощником при диагностике.

**Работает только через компьютер**: диагностика, софт, Toolbox, отчёты. Пайку, замену железа, ремонт батарей/приводов/MCU не предлагать — такое владелец отдаёт партнёрам.

Этот ноутбук — **рабочий Windows-ноутбук**, который подключается к машине. Подготовка проекта сделана на MacBook 2026-10-19.

## Что есть
- **История машины** по VIN (`app.py`: `car_summary`, `render_car_history`, страница `/car/<VIN>`, API `/api/cars`, `/api/car/<VIN>`). Отдельной базы нет — история собирается из `jobs/*.json` по `client.vin`, цифры визитов берутся из JSON отчётов. VIN всегда хранится в верхнем регистре. При вводе знакомого VIN программа подставляет клиента и показывает число визитов.
- **Нормы по модели/году** (`specs.py`): варианты Model 3/Y/S/X по годам (ёмкость, химия NCA/NMC/LFP, тип 12V: свинцовый или литиевый ~16V примерно с конца 2021, давление шин). Комплектация выбирается в карточке клиента или угадывается по `BattBeginningOfLifeEnergy292`. Деградация сравнивается с типичной для пробега (`DEGRADATION_CURVE`). Все цифры — ориентиры из открытых источников; уточнять по реальным машинам.
- **VIN** (`vin.py`): модель, год, завод, страна, вероятный рынок (5YJ/7SA → US-версия, нужна локализация), проверка контрольной цифры. В программе VIN сам заполняет модель и год.
- Давление шин (`ID31FTPMSsensors`) идёт по ChassisBus — с разъёма vehicle-шины может не прийти; проверить на реальной машине.
- **Схема машины** (`carmap.py`): вид сверху, 8 зон (front/cameras/screen/connectivity/battery/tires/rear/charge), цвет по худшей находке. Находки — `[level, text, zone]`, предупреждения машины → зоны через `ALERT_ZONES`. Новую проверку привязывать к зоне. Зоны cameras и charge пока всегда «нет данных» — нужны сигналы с реальной машины.
- **Три языка (ru / en / ka)**: все тексты в `i18n.py`, тексты услуг — в `services.py` через `L(ru, en, ka)`. Язык выбирается в шапке программы (`settings.json` → `lang`), отчёты и акты делаются на текущем языке. Грузинский перевод сделан Claude — стоит проверить носителю. Новый текст добавлять сразу на трёх языках.
- `app.py` + `ui/index.html` + `services.py` — программа с кнопками услуг (локальный веб-сервер на stdlib, порт 8765, `--lan` для телефона). Заказы в `jobs/*.json`, настройки в `settings.json`, акты `reports/act-*.html`. Каталог услуг — `services.py` (mode: auto / guided / partner).
- `tesla.py` — диагностика Model 3/Y по CAN, только чтение:
  - `listen` — запись с адаптера в `logs/*.asc` (pcan: PASSIVE, slcan: listen_only)
  - `report` — HTML-отчёт для клиента + JSON в `reports/`
  - `simulate` — тестовый лог без машины
- `dbc/Model3CAN.dbc` — DBC сообщества (joshwardell/model3dbc, MIT), основной. Остальные `dbc/tesla_*.dbc` — из commaai/opendbc (MIT), для справки, в коде не используются.
- Шина Model 3/Y — vehicle CAN, 500 kbit/s.

## Правила
- **Только чтение.** Никогда не отправлять кадры в шину и не писать в блоки машины без явного согласия владельца после объяснения рисков.
- Работа с высоким напряжением — только с напоминанием о безопасности.
- Не помогать обходить защиту Tesla (взлом, разблокировка платных функций, обход блокировок Supercharger).
- Процедуры Tesla Toolbox 3 (калибровки, прописка блоков) владелец запускает сам в Chrome; Claude по скриншотам и спискам ошибок объясняет, что делать.
- Пороги в отчёте (разбаланс 30/80 мВ, деградация 15/25%, 12V < 12.2 В) — ориентиры, не официальные значения Tesla.

## Возможные следующие шаги

- Журнал клиентов/машин, шаблон цены в отчёте.
- Поддержка Model S/X (другая шина и DBC: `dbc/tesla_can.dbc`).
